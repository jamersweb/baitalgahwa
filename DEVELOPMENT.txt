Bait Al Gahwa (theme_baitalgahwa) — internal notes
================================================

Build / AMD
- From the full Moodle project root, run: `grunt amd` (or the site’s Gruntfile target) so `theme/baitalgahwa/amd/build/theme.min.js` stays in sync with `amd/src/theme.js`. After SCSS or string changes, Purge all caches; if SCSS fails on large themes, check PHP `max_execution_time` and the Moodle environment report.

Deploy / live site
- moodle.acusync.net (or any host) only picks up changes after this theme folder is updated on the server and **Site administration → Development → Purge all caches** is run. There is no CI in this repo; missing deploy or skipped purge looks exactly like “CSS not applying”.
- Enrol hub detection in lib.php uses path suffix matching so subdirectory installs (e.g. `/moodle/enrol/index.php`) still get `baitalgahwa-course-enrol`; plain `/enrol/index.php` worked before only by accident.
- If enrol hero/summary never appears but width CSS does: `course_dashboard` was false (URL/path detection). lib.php now falls back when **SCRIPT_NAME** contains `enrol/index.php` and re-builds context with `$forceenrolhub`. Summary layout also ships as **`baitalgahwa-enrol-summary-critical`** inline in `drawers.mustache` (search page source).
- If enrol width still never changes after deploy + purge: open **View page source** on `/enrol/index.php` and search for **`baitalgahwa-enrol-width-critical`**. If it is missing, Moodle is **not** rendering **theme_baitalgahwa/drawers** (e.g. site default theme is RemUI only). Switch theme to Bait Al Gahwa or paste equivalent rules into RemUI Custom CSS.

Reference assets
- Design PNG mockups in `assets/` (if present) map to: layouts under `layout/`, templates under `templates/`, and SCSS under `scss/` (e.g. my courses: `mycourses.scss` + `block_myoverview` overrides, course home: `course-view.scss` + `course_dashboard_hero.mustache`).

Enrol hub (/enrol/index.php) — backend vs theme
- Core flow (see Moodle `enrol/index.php`): logged-in users see `course_info_box` plus one block per enrol instance that returns a form from `enrol_page_hook()`. If **no** instances expose a form, core calls `notice(get_string('notenrollable','enrol'), …)` which renders `#notice.box.generalbox` and a Continue button (`lib/weblib.php` `notice()`). Fixing “cannot enrol yourself” requires **course enrolment methods** in Moodle (e.g. enable **Self enrolment** on the course, guest access, payment plugins, etc.), not theme CSS alone.
- Guests hit `noguestaccess` the same way (`notice()`). Not logged in → redirect to login (`wantsurl` set to the course view URL).
- Already enrolled → redirect away before the hub renders.
- **Custom fields** (phone, city, country): use Moodle **User profile fields** (required or optional) and map collection through enrol plugins / signup — or a `local_` plugin using enrol APIs. This theme styles core `form.mform` on the enrol page when plugins output forms; it does not create enrol instances or store arbitrary POST data without a Moodle plugin.
- **Course image**: overview files come from the course’s overview files area; a missing or broken image URL is a course/content issue. Layout fixes assume a valid `<img>` inside `.courseimage`.
